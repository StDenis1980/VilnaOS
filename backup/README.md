# Vilna Backup

Зашифровані резервні копії даних Vilna: налаштування, дані Gloxi і Herkos, база KeePassXC, обрані папки. Усе шифрується на пристрої у форматі restic; пароль сховища тримає сховище ключів (GNOME Keyring), Gloxi його не бачить.

Рішення — [ADR 0007](../docs/adr/0007-encrypted-backup.md), деталі — [`docs/design.md`](docs/design.md).

## Стан: прототип

Є:

- **Місця:** локальний диск або USB, SFTP, S3, rest-server (наш сервер у ЄС). Логіни до S3 і rest-server — у сховищі ключів, не в налаштуваннях.
- **Ключі:** пароль сховища (256 біт) генерується на пристрої і лежить у GNOME Keyring через `secret-tool`; restic бере його сам (`RESTIC_PASSWORD_COMMAND`), тож пароль не потрапляє ні в командний рядок, ні в змінні середовища, ні до Gloxi. Ключ відновлення — другий ключ restic, 8 груп по 4 знаки, показується один раз.
- **Аркуш відновлення обов'язковий:** поки людина не введе ключ відновлення з аркуша, копії не вмикаються (design.md 3а).
- **Що зберігати** (design.md 2а): «лише налаштування», «налаштування і документи» (за замовчуванням), «уся домашня», «вибрати самому»; додати чи прибрати папку; історія розмов Gloxi — лише за згодою; секрети системи (ключниця, облікові записи, SSH, GPG) — лише за окремою згодою людини в терміналі. Розміри груп папок і перевірка ліміту з порадою, які великі папки не брати.
- **Ніколи не зберігаються:** кеші, Завантаження (у «уся домашня»), кошик, ваги моделей (`*.gguf`), копії скасування Herkos. Список Flatpak-застосунків і `dconf dump` знімаються перед кожною копією.
- **Розклад:** таймери systemd користувача: копія щогодини/щодня/щотижня, перевірка `restic check` щотижня і читання 5 % даних раз на місяць.
- **Відновлення:** у нову порожню папку (можна один файл чи папку) або поверх домашньої папки — лише людина в терміналі, після переліку файлів, які буде замінено. На новому пристрої — `vilna-backup recover` з ключем відновлення; для пристрою створюється власний ключ.
- **Для Gloxi:** MCP-сервер [`mcp/backup`](../mcp/backup/) і маніфест Herkos з рівнями design.md 5. Gloxi може лише R0–R2: стан, список копій, розміри, що і як часто зберігати, «зробити копію зараз», відновлення в нову папку.

Ще немає: фрази відновлення (Argon2id, потрібен наш сервер), PDF аркуша з QR, пристроїв і блокування, вікна Herkos замість терміналу, розмови Gloxi з розд. 2а, ключа в TPM2, журналу запусків у Mitos (поки свій журнал `runs.jsonl` без шляхів і назв файлів).

## Як спробувати

Потрібні `restic` ≥ 0.17 і `secret-tool` (пакет `libsecret-tools` / `libsecret`).

```sh
cd backup
uv sync
uv run vilna-backup set --preset documents --limit-gb 50
uv run vilna-backup overview                 # розміри і чи вміщається
uv run vilna-backup setup /run/media/$USER/USB/vilna   # покаже ключ відновлення
uv run vilna-backup run                      # копія зараз
uv run vilna-backup snapshots
uv run vilna-backup restore --target ~/Documents/Відновлено --path Documents/zvit.odt
uv run vilna-backup check --read-data
uv run pytest                                # тести зі справжнім restic
```

Без GNOME Keyring (наприклад, на сервері для тестів) ключі можна тримати у файлах: `VILNA_BACKUP_KEYSTORE=file:/шлях`. Це лише для випробувань.
