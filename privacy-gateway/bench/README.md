# Заміри шлюзу приватності

Два заміри з етапу «листопад — грудень 2026» [ADR 0021](../../docs/adr/0021-vilna-skia.md). Код не входить у бібліотеку і потрібен лише для рішень: який формат замінників брати і яку модель імен ставити на пристрій.

Усі тексти в `pg_bench/data/` вигадані. Їх навмисно надсилають у хмарні моделі, тому справжні дані сюди не додаємо ніколи.

## 1. Формат замінників

Чи повертають хмарні моделі замінник без змін? 14 завдань десятьма мовами ([ADR 0009](../../docs/adr/0009-languages.md)): переписати, перекласти, скласти таблицю чи JSON, усе малими літерами, відповісти на лист, пояснити налаштування з ключем. Кожне завдання маскується справжнім `Masker`, а замінники переписуються в один із п'яти форматів:

| Назва | Вигляд |
| --- | --- |
| `square` | `[EMAIL_1]` (зараз) |
| `double` | `[[EMAIL_1]]` |
| `curly` | `{{EMAIL_1}}` |
| `angle` | `<EMAIL_1>` |
| `white` | `⟦EMAIL_1⟧` |

Кожен формат іде двічі: без пояснень (`none`) і з короткою вказівкою в системному повідомленні копіювати замінники як є (`hint`). Зараз Gloxi такої вказівки не надсилає, тож замір покаже, чи варто її додати.

Для кожного замінника у звіті одне з чотирьох:

- **точно** — повернувся без змін;
- **змінено** — модель його змінила (`[Email_1]`, `{EMAIL 1}`), але `unmask` значення відновив;
- **зламано** — у відповіді є щось схоже на замінник, але значення не відновилося (`[ОСОБА_1]`);
- **немає** — замінника у відповіді немає. Для завдань `keep = "some"` (підсумок, лист) це не провал.

### Як запустити

Ключі лишаються на вашому комп'ютері, у файлі поза репозиторієм і поза OneDrive. У звіт вони не потрапляють.

```sh
cd privacy-gateway
mkdir -p ~/.config/vilna-bench
cp bench/keys.env.example ~/.config/vilna-bench/keys.env
chmod 600 ~/.config/vilna-bench/keys.env
nano ~/.config/vilna-bench/keys.env    # впишіть ключі після «=»

uv run python bench/run.py placeholders \
  --model anthropic:claude-haiku-4-5 \
  --model openai:gpt-5-mini \
  --model google:gemini-2.5-flash \
  --model mistral:mistral-small-latest
```

Замір читає лише чотири відомі назви ключів, а файл, який можуть читати інші користувачі, не бере. Змінна, вже задана в терміналі, важить більше за файл. Інший файл задає `--keys шлях`. Після заміру ключі краще відкликати або видалити файл.

Назви моделей тут — приклади: перевірте актуальні на сторінках постачальників. Без ключа одного постачальника просто приберіть його `--model`. `--format square --prompt hint` звужує замір, `--only pl` бере лише завдання, в id яких є `pl`, `--repeat 3` повторює кожен запит (моделі відповідають щоразу трохи інакше). Повний замір — 140 запитів на модель, кожен на кілька сотень токенів, тож на дешевих моделях це центи.

`local:<модель>` надсилає ті самі завдання в будь-який сервер, сумісний з OpenAI, на `--local-url` (типово llama-server на `127.0.0.1:8080`).

Звіт: `bench-results/placeholders-<дата>.md` (таблиця і кожна невдала відповідь) і `.json` з усіма відповідями.

## 2. Модель імен

Зараз шлюз ховає ім'я лише в полі з підписом (`Ім'я: …`, `Name: …`). Цей замір показує, наскільки добре мала модель на пристрої знаходить імена у вільному тексті. 100 речень, по 10 на мову: імена у відмінках (`Ірині Бондар`, `Tomaszem Wiśniewskim`, `Petraičiui`), звертання (`Андрію`, `Kasiu`), прізвище окремо (`з паном Мельником`), і пастки — міста, річки, компанії й звичайні слова, що бувають іменами (`надія`, `Віра`, `Škoda`).

Ім'я зараховане, лише якщо модель накрила його повністю: сховати «Олена», але лишити «Коваль» — однаково витік, це «частково».

```sh
cd privacy-gateway
uv run python bench/run.py names --backend regex      # нинішній шлюз, для порівняння: 0 %
uv run python bench/run.py names --backend llm:qwen3-4b   # модель Gloxi через llama-server
uv run --with gliner --with sentencepiece --with tiktoken --with protobuf \
  python bench/run.py names --backend gliner:urchade/gliner_multi_pii-v1
uv run --with spacy python bench/run.py names --backend spacy:xx_ent_wiki_sm
```

`llm:` працює лише з сервером на цьому ж комп'ютері (`127.0.0.1`): розпізнавання імен не має виходити з пристрою. Для spaCy модель спершу треба завантажити: `uv run --with spacy python -m spacy download xx_ent_wiki_sm`. `--lang uk --lang pl` бере лише ці мови.

Кандидати (ліцензію перевірити в картці моделі перед вибором):

| Модель | Розмір | Ліцензія |
| --- | --- | --- |
| Qwen3 4B (вже в Gloxi, ADR 0008) | 0 додатково | Apache-2.0 |
| GLiNER multi PII v1 | ≈ 0,3 млрд параметрів | Apache-2.0 |
| GLiNER multi v2.1 | ≈ 0,3 млрд параметрів | Apache-2.0 |
| spaCy `xx_ent_wiki_sm` | ≈ 10 МБ | MIT |

Як обираємо (пропозиція): повнота від 90 % на кожній з 10 мов, не більше одного зайвого спрацювання на 10 речень, до 100 мс на речення на процесорі для малої моделі. Якщо Qwen3 4B точніша за GLiNER, але повільніша, її можна кликати лише для повідомлень у хмару, де секунда затримки прийнятна.

Звіт: `bench-results/names-<модель>-<дата>.md` (таблиця за мовами і кожна помилка).

## Тести

`tests/test_bench.py` перевіряє сам підрахунок на підставних моделях: та, що копіює замінники, проходить усе; малі літери — «змінено»; `[ОСОБА_1]` — «зламано»; пропущене значення — провал лише там, де мало лишитися все.
