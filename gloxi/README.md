# Gloxi

Gloxi («Глоксі», від *glaux* — сова Афіни) — AI-асистент Vilna.

Тут буде:

- системний сервіс Gloxi (працює під окремим користувачем, без прямого доступу до системи);
- маршрутизатор моделей: приватне й просте — локально (мала модель 1–3B), складне — у хмару;
- клієнт MCP, що підключає інструменти;
- окремо — прототип Gloxi як застосунку для звичайного Linux.

Усі дії Gloxi виконує лише через шлюз дозволів Herkos — див. [`../herkos/docs/permissions.md`](../herkos/docs/permissions.md).

## Стан

Каркас Gloxi 0.1 preview (див. [roadmap](../docs/roadmap.md), розд. 2.3–2.4): чат у терміналі з локальною моделлю через `llama-server` і маршрутизатор «локально / хмара за ключем користувача». Є вікно чату на GTK 4 / libadwaita, шлюз приватності для хмари і робота з файлами через Herkos-lite.

## Запуск для розробки

Покрокова інструкція для тестувальників — у [`../docs/getting-started.uk.md`](../docs/getting-started.uk.md) ([English](../docs/getting-started.md), [Español](../docs/getting-started.es.md)).

Потрібні Python ≥ 3.11 і [uv](https://docs.astral.sh/uv/).

1. Запустіть локальну модель через [llama.cpp](https://github.com/ggml-org/llama.cpp) ([ADR 0004](../docs/adr/0004-local-model-engine.md)). Підійде будь-яка мала instruct-модель у форматі GGUF. За замірами пропонуємо Qwen3 4B без «роздумів» ([ADR 0008](../docs/adr/0008-default-local-model.md)):

   ```sh
   llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --port 8080 -c 4096 \
     --chat-template-kwargs '{"enable_thinking":false}'
   ```

2. Поговоріть з Gloxi:

   ```sh
   cd gloxi
   uv sync
   uv run gloxi            # інтерактивний чат: /reset, /backup, /exit
   uv run gloxi ask "Що вмієш?"
   ```

Gloxi говорить з моделлю лише через OpenAI-сумісний API, тож замість `llama-server` можна вказати Ollama чи інший сервер: `--url http://127.0.0.1:11434/v1 --model qwen2.5:1.5b` або змінна `GLOXI_LOCAL_URL`.

### Вікно чату (GTK)

Вікно потребує PyGObject, GTK 4 і libadwaita із системи (у Flatpak вони прийдуть із рантайму GNOME). На Aeon усе ставимо в toolbox, на Fedora чи Ubuntu — прямо в систему:

```sh
# Fedora / toolbox на Aeon
sudo dnf install python3-gobject gtk4 libadwaita
# Ubuntu / Debian
sudo apt install python3-gi gir1.2-gtk-4.0 gir1.2-adw-1

cd gloxi
python3 -m venv --system-site-packages .venv-gtk
.venv-gtk/bin/pip install -e ../privacy-gateway -e ../mcp/files -e ../herkos -e ".[tools]"
.venv-gtk/bin/gloxi-gtk
```

Локальні пакети треба перелічити явно: pip не читає `[tool.uv.sources]` і шукав би їх на PyPI.

У заголовку вікна видно, чи ввімкнена хмара. Над кожною відповіддю написано, де її отримано: «На цьому комп'ютері» або «Хмара: host, з маскуванням». Перемикач моделі ліворуч від поля введення (або Ctrl+/) змінює модель і посеред розмови, з наступного повідомлення: «Авто» (маршрутизатор), «Локальна» або «Хмара». Підказка на перемикачі каже, куди піде повідомлення і чи маскуються особисті дані. Поки хмару не ввімкнено, є лише «Локальна». Вибір діє до закриття Gloxi, файл налаштувань не змінюється. `/local` і `/cloud` на початку повідомлення обирають модель для одного повідомлення, як у терміналі. Кнопка «+» починає нову розмову. Мова інтерфейсу — мова системи (див. «Мови інтерфейсу»).

### Налаштування

`~/.config/gloxi/config.toml` (необов'язково):

```toml
[local]
url = "http://127.0.0.1:8080/v1"
model = "local"
timeout = 120

[cloud]                      # необов'язково: свій провайдер і свій ключ
url = "https://api.mistral.ai/v1"
model = "mistral-small-latest"
# api_key = "..."            # краще змінна GLOXI_CLOUD_API_KEY

[router]
mode = "auto"                # auto | local | cloud
cloud_allowed = false        # хмара вимкнена, доки користувач її не ввімкне
long_message_chars = 1500    # auto: довші повідомлення йдуть у хмару
mask_cloud = true            # шлюз приватності: маскувати особисті дані перед хмарою
```

Змінні середовища мають пріоритет над файлом: `GLOXI_LOCAL_URL`, `GLOXI_LOCAL_MODEL`, `GLOXI_LOCAL_TIMEOUT`, `GLOXI_CLOUD_URL`, `GLOXI_CLOUD_MODEL`, `GLOXI_CLOUD_API_KEY`, `GLOXI_CLOUD_ALLOWED`, `GLOXI_ROUTER_MODE`, `GLOXI_MASK_CLOUD`.

### Маршрутизатор

1. Без `cloud_allowed = true` і налаштованого `[cloud]` нічого не залишає комп'ютер.
2. `/local <текст>` або `/cloud <текст>` обирає модель для одного повідомлення.
3. `mode = "local"` або `"cloud"` (чи `--mode`) закріплює модель для всіх повідомлень.
4. `mode = "auto"`: прості повідомлення — локально, довші за `long_message_chars` — у хмару. Це стартове правило, його уточнимо на замірах.

Якщо локальна модель не відповідає, Gloxi **не** переходить у хмару сам, а показує помилку. Перед кожною відповіддю видно, куди пішло повідомлення: `[local]` або `[cloud: api.mistral.ai, masked]`.

### Шлюз приватності

Усе, що йде в хмару, спершу проходить через [шлюз приватності](../privacy-gateway/README.md) на цьому комп'ютері: пошта, телефони, номери документів і рахунків, ключі та паролі, підписані поля з ім'ям, датою народження чи адресою замінюються на `[EMAIL_1]`, `[PHONE_1]` тощо. Хмарна модель бачить лише замінники, а у відповіді Gloxi повертає справжні значення. В історії розмови лишаються справжні значення; замінники існують тільки в запиті до хмари і забуваються, коли починається нова розмова. Імена у вільному тексті шлюз поки не розпізнає.

Паролі й ключі, які людина пише в чаті, Gloxi ховає від будь-якої моделі, і від локальної теж: модель отримує `[SECRET_1]`, а якщо повторить його у відповіді, Gloxi покаже `••••••`, не сам пароль. Так само замінник, а не пароль, потрапляє в аргументи інструментів. Це працює завжди, навіть з `mask_cloud = false`, бо моделі повторюють паролі ([ADR 0008](../docs/adr/0008-default-local-model.md)).

`mask_cloud = false` вимикає маскування. Тоді біля кожної хмарної відповіді написано `not masked`.

### Файли через Herkos

Якщо запущено Herkos-lite (`herkos serve`, див. [`../herkos/README.md`](../herkos/README.md)), локальна модель отримує функції `files_list`, `files_search`, `files_read`, `files_create` і `files_write` для папок, які дозволено в налаштуваннях Herkos. Сам Gloxi файлів не торкається: кожен виклик іде в Herkos, той перевіряє рівень, за потреби питає людину у своєму вікні (з поясненням Gloxi, навіщо це), виконує дію і пише журнал. Відмову Gloxi отримує як звичайну відповідь і пояснює її людині. У чаті видно кожен виклик, наприклад `[files: read ~/Documents/plan.txt (done)]`.

Інші програми, які Herkos запускає й показує в `herkos.tools` (ADR 0017, етап 2), стають функціями для моделі за схемами параметрів, які дала сама програма й перевірив Keros: одна функція на операцію, назва `<програма>_<операція>` (наприклад `notes_read`), до схеми Gloxi додає поле `reason`. Аргументи, які Herkos позначив як файли (`resource_args`), Gloxi робить абсолютними шляхами й надсилає ще й як ресурси дії, щоб Herkos звірив їх із дозволеними теками. Результат програми з `returns_external` — зовнішні дані в межах Keros, як і вміст файлів. Функцій програм за раз щонайбільше 8 (`MAX_PROGRAM_FUNCTIONS`); коли їх більше, першими йдуть ті, чиї назва й опис мають найбільше спільних слів із повідомленням людини. Скільки функцій витримує Qwen3 4B, ще треба заміряти на gloxi-bench. Резервні копії (`org.vilna.mcp.backup`) моделі не пропонуються.

Програми з каталогу вимкнені, доки людина не ввімкне їх на сторінці «Програми для Gloxi» (кнопка в заголовку вікна; з'являється, коли Herkos знає хоч одну програму). Перемикачі зберігає сам Herkos (`herkos.programs`, `herkos.set_program`), а перед увімкненням питає людину у власному вікні, тож ні Gloxi, ні модель не можуть увімкнути програму самі. Вимкнена програма не запускається, а її дії Herkos відхиляє. На тій самій сторінці видно дії, які Herkos приховав від моделі, і чому.

- Видаляти файли Gloxi 0.1 не може: це R3, а Herkos-lite виконує лише R0–R2.
- Після читання чи пошуку розмова вважається «забрудненою» (у ній є чужий текст), тож зміна файлу стає R3. Herkos-lite все одно питає, але дозволяє лише «один раз» і показує точно, що буде записано ([`permissions.md`](../herkos/docs/permissions.md), розд. 4.2). Якщо Keros знайшов у прочитаному ознаки атаки, зміни заборонено до нової розмови (`/reset` або «Нова розмова»).
- Вміст файлів модель бачить лише всередині меж Keros (`herkos.keros.wrap`), які текст файлу не може закрити. Якщо Keros знаходить у файлі ознаки ін'єкції (наприклад, «ignore all previous instructions»), Gloxi показує попередження в чаті, а модель отримує примітку не виконувати цих вказівок.
- Вміст файлів не потрапляє в історію розмови, а хмарна модель функцій не отримує: файли лишаються на цьому комп'ютері.
- Модель має вміти викликати функції: `llama-server` потрібен із шаблоном чату, що знає інструменти (`--jinja`, у свіжих збірках так за замовчуванням).
- `[tools] enabled = false` або `GLOXI_TOOLS=0` вимикає функції. Без Herkos Gloxi просто розмовляє.

Для розробки Herkos ставиться разом із Gloxi (`uv sync`), а для пакета — як додаткова залежність `gloxi[tools]`.

### Копії: перша розмова

Якщо запущено Herkos-lite з інструментом «копії» ([`../mcp/backup/`](../mcp/backup/)), Gloxi на першому запуску (у терміналі й у вікні) питає про резервні копії за сценарієм [`backup/docs/design.md`](../backup/docs/design.md), розд. 2а: чи зберігати, що саме (з реальними розмірами папок), чи брати історію розмов, скільки місця (і які великі папки не брати, якщо не вміщається), куди і як часто. Це фіксований сценарій, а не модель: назви папок і розміри не потрапляють у жодну модель. Кожна зміна йде через Herkos, тож перший раз людина бачить його вікно.

- Місце зберігання і ключ відновлення — R3, тому останній крок людина робить сама: Gloxi дає готову команду `vilna-backup setup …` (згодом це буде вікно Herkos). Перша копія починається одразу після підтвердження аркуша.
- «Пізніше» — Gloxi спитає ще раз через тиждень, потім більше ні. `/backup` починає розмову будь-коли.
- Тексти перекладено, як і решту інтерфейсу (див. «Мови інтерфейсу»).

### Бічна панель (етап A)

Вікно Gloxi — бічна панель біля правого краю екрана ([план вікна](https://claude.ai/artifact/LC8CETBDgTmYEHvt8fVADJ), рішення Denys від 2 листопада 2026). Кнопка з панеллю в заголовку відкриває розмір і вигляд:

- **Розмір:** «Мала» (сова, останні 2–3 рядки чату й поле введення, унизу праворуч), «1/6» і «1/3» ширини екрана на всю висоту; Ctrl+1, Ctrl+2, Ctrl+3. Якщо потягнути за край, Gloxi запам'ятає власний розмір людини.
- **Напівпрозора** (за замовчуванням увімкнено, тло непрозоре на 80 %, повзунок від 40 до 100 %). Бульбашки повідомлень лишаються непрозорими, тож текст читається на будь-яких шпалерах. За високого контрасту прозорість вимикається сама.
- **Поверх інших вікон** (за замовчуванням увімкнено).
- **Сова** в заголовку показує стан: готовий, слухає (фокус у полі введення або відкритий мікрофон), міркує, відповідає, чекає на людину (золота мітка), помилка (червона мітка). Стан дублюється підказкою і для читачів екрана; анімація вимикається разом із системним «Зменшити анімацію».

На Wayland програма не може сама стати біля краю чи поверх інших вікон, тому це робить розширення GNOME Shell Vilna ([`../shell-extension/`](../shell-extension/README.md)): Gloxi лише каже йому розмір через D-Bus. Без розширення (Flatpak на іншому Linux) панель має той самий розмір, але місце обирає GNOME, а перемикача «поверх інших вікон» немає. Налаштування панелі лежать у `~/.config/gloxi/window.json` (у Flatpak — `~/.var/app/io.github.stdenis1980.Gloxi/config/gloxi/`). Код: `src/gloxi/gui/panel.py` (логіка без GTK, `tests/test_panel.py`), `src/gloxi/gui/shell.py` (D-Bus).

### Голос (кроки 1–2 ADR 0015)

[ADR 0015](../docs/adr/0015-gloxi-voice.md). Усе на цьому комп'ютері: звук нікуди не йде і на диск не пишеться, у журнал розмови потрапляє лише текст.

- **Диктування.** Кнопка мікрофона в полі введення або Ctrl+M: Gloxi слухає одну фразу, поки людина не замовкне (Silero VAD, 1,2 с тиші), не натисне ще раз або не мине хвилина; Esc скидає фразу. Parakeet TDT 0.6B v3 перетворює звук на текст із розділовими знаками, і текст стає в поле введення. Надсилає людина сама; «Надсилати продиктований текст одразу» в меню панелі вмикає автонадсилання (за замовчуванням вимкнено). Модель (≈1 ГБ у пам'яті) завантажується при першому натисканні й вивантажується після 5 хвилин без диктування.
- **Читання вголос.** «Читати відповіді вголос» у меню панелі (за замовчуванням вимкнено). Gloxi сам визначає мову відповіді і читає її відповідним голосом по реченню, тож перше речення чути, поки решта ще готується. Кнопка «Стоп» або Esc обривають читання; натиснутий мікрофон спершу вимикає голос (півдуплекс). Прихований пароль Gloxi вимовляє як «пароль приховано», Markdown і адреси не читає, код — лише «код показано на екрані».
- **Згода.** Без «так» нічого не завантажується. Gloxi показує кожну модель, її розмір, ліцензію і звідки вона, і теку, куди покладе (`~/.local/share/gloxi/models/voice`, у Flatpak — `~/.var/app/io.github.stdenis1980.Gloxi/data/gloxi/models/voice`). Архіви перевіряються за SHA-256 з `src/gloxi/voice/models.py` і розпаковуються без посилань і шляхів назовні.

| Що | Модель | Розмір | Ліцензія | Автор |
| --- | --- | --- | --- | --- |
| Розпізнавання, 25 мов | NVIDIA Parakeet TDT 0.6B v3, int8 | 487 МБ | CC-BY-4.0 | NVIDIA; ONNX — sherpa-onnx |
| Кінець мовлення | Silero VAD | 1 МБ | MIT | Silero Team |
| Голос uk | Piper uk_UA ukrainian_tts medium (голос «Микита») | 80 МБ | CC0-1.0 | Rhasspy Piper, NabuCasa voice-datasets |
| Голоси en, es, it, fr | Kokoro-82M v1.0, int8 | 132 МБ | Apache-2.0 | hexgrad; французький голос — SIWIS (CC-BY-4.0) |
| Голоси pl, cs, ro, de | Piper gosia, jirka, mihai, thorsten (medium) | по 67 МБ | CC0-1.0 | Rhasspy Piper; ONNX — sherpa-onnx |
| Литовська і фонеми для Kokoro та Piper | eSpeak NG 1.52 (у пакеті) | — | GPL-3.0-or-later | eSpeak NG |

Для української людина завантажує ≈568 МБ, для англійської, іспанської, італійської, французької ≈620 МБ, для польської, чеської, румунської, німецької ≈555 МБ, для литовської ≈488 МБ. RHVoice (розд. 2.1 ADR) sherpa-onnx не читає, тож pl, cs, ro читають голоси Piper; литовський ingute (розд. 2.3) ще не закріплено, бо йому потрібен власний фонемізатор, і поки литовську читає eSpeak NG.

```sh
uv sync --extra voice                       # sherpa-onnx; ще потрібні espeak-ng і GStreamer (PyGObject)
uv run gloxi voice status                   # що завантажено і який голос читає кожну мову
uv run gloxi voice download                 # спитати й завантажити для мови інтерфейсу
uv run gloxi voice say "Привіт, я Gloxi."   # прочитати вголос
uv run gloxi voice listen                   # одна фраза з мікрофона → текст
uv run gloxi-bench --tasks voice            # 10 мов: озвучити фразу й розпізнати її, WER і швидкість
GLOXI_VOICE_MODELS=~/.local/share/gloxi/models/voice uv run pytest tests/test_voice.py
```

Код: `src/gloxi/voice/` (`session.py` — логіка без GTK, `stt.py`, `tts.py`, `audio.py` — мікрофон і динаміки через GStreamer), тести — `tests/test_voice.py`.

### Відгуки й звіти про збої

[ADR 0018](../docs/adr/0018-error-reports-and-feedback.md), крок для 0.1. `/feedback`, кнопка з конвертом у заголовку вікна або коротке повідомлення на кшталт «Повідом про помилку», «I have a suggestion» (10 мов, лише на початку повідомлення) починають розмову про відгук. Це фіксований сценарій, а не модель (`src/gloxi/feedback.py`): що сталося і що очікували (або сама пропозиція), чи додати блок `gloxi check` і останній звіт про збій. Шлюз приватності ховає пошту, телефони, ключі тощо ще до показу, і Gloxi каже, що саме приховано. Далі людина бачить усю чернетку і попередження, що форма публічна; лише після «Відкрити форму» Gloxi відкриває в браузері форму GitHub `gloxi-feedback` із заповненими полями. Надсилає її людина сама, у браузері; сам Gloxi нічого не відправляє. Схоже на вразливість («bypass», «обійти»…) — Gloxi радить приватний канал із `SECURITY.md` і форму не відкриває. `/cancel` зупиняє розмову.

Якщо Gloxi падає з необробленою помилкою (у будь-якому потоці), він пише короткий звіт у `~/.local/state/gloxi/crashes/` (у Flatpak — у `~/.var/app/io.github.stdenis1980.Gloxi/.local/state/`): версія, тип помилки і рядки traceback лише з `gloxi`, `herkos`, `privacy_gateway`, без тексту помилки й повних шляхів (`src/gloxi/crash.py`). Звіт нікуди не йде; `/feedback` протягом тижня пропонує його додати. Зберігаються останні 10.

### Flatpak

Маніфест — [`flatpak/io.github.stdenis1980.Gloxi.yml`](flatpak/io.github.stdenis1980.Gloxi.yml): рантайм GNOME, бібліотеки Python у версіях з `uv.lock` (це перевіряє `tests/test_flatpak.py`), сам Gloxi, шлюз приватності, Herkos-lite та інструмент «файли». CI збирає пакет і перевіряє, що він запускається; готовий `gloxi.flatpak` лежить в артефактах запуску.

```sh
flatpak-builder --user --install --force-clean build flatpak/io.github.stdenis1980.Gloxi.yml
flatpak run io.github.stdenis1980.Gloxi                      # вікно
flatpak run --command=gloxi io.github.stdenis1980.Gloxi      # термінал
flatpak run --command=gloxi io.github.stdenis1980.Gloxi check  # чи потягне залізо; блок для відгуку
```

У пісочниці Gloxi має мережу (локальна модель на `127.0.0.1` і хмара, якщо її ввімкнено) і більше нічого: доступу до файлів немає. Herkos-lite і інструмент «файли» лежать у тому ж пакеті; Gloxi сам запускає Herkos окремим процесом (`src/gloxi/herkos_local.py`), і сокет лишається всередині пісочниці. Теки, з якими Gloxi може працювати, людина обирає кнопкою з текою в заголовку вікна: відкривається системне вікно вибору (портал документів), і лише обрані теки стають видимими й потрапляють у `allowed_roots` Herkos. Поки тек не обрано, інструментів немає. Це слабше, ніж у Vilna, де Herkos — системна служба поза сеансом людини; опис пакета про це каже. Налаштування Gloxi лежать у `~/.var/app/io.github.stdenis1980.Gloxi/config/gloxi/config.toml`, Herkos — поруч, у `config/herkos/config.toml`, журнал дій Herkos — у `.local/state/herkos/journal.jsonl` там само.

Herkos питає людину у своєму вікні, а якщо робочого столу немає і Gloxi запущено в терміналі, то в тому самому терміналі: Gloxi передає йому свій термінал. Відповідь вводить людина, модель її не бачить і не може ввести. Коли Gloxi закривають (вікно, Ctrl+C, закритий термінал чи `kill`), він зупиняє і модель, і Herkos. Резервних копій у пакеті немає (вони частина Vilna), тож Gloxi про них не питає.

Перевірити роботу з обмеженням пам'яті: `systemd-run --user --scope -p MemoryMax=8G flatpak run …` не діє, бо Flatpak переносить застосунок у власний scope. Обмеження ставимо вже на нього: `systemctl --user set-property --runtime app-flatpak-io.github.stdenis1980.Gloxi-<номер>.scope MemoryMax=8G MemorySwapMax=0`, а пік дивимося в `memory.peak` цього scope. `VmHWM` процесу `llama-server` тут мало що каже: на вбудованій відеокарті ваги лежать у спільній пам'яті GPU.

У пакеті є `llama-server` (llama.cpp b12048, CPU і Vulkan). Якщо на `[local] url` ніхто не відповідає, Gloxi запускає його сам, лише на `127.0.0.1` ([ADR 0004](../docs/adr/0004-local-model-engine.md)). Моделі в пакеті немає: на першому запуску Gloxi питає, чи завантажити Qwen3 4B (≈2,5 ГБ, [ADR 0008](../docs/adr/0008-default-local-model.md)), і без «так» нічого не завантажує: після відмови Gloxi у терміналі пояснює, що без моделі не відповідатиме, і завершується (якщо не ввімкнено хмару). Файл перевіряється за SHA-256 з `src/gloxi/engine.py` і лежить у `~/.var/app/io.github.stdenis1980.Gloxi/data/gloxi/models`; перерване завантаження продовжується. На комп'ютерах від 16 ГБ Gloxi після першого запуску один раз, ≈1 хв, перевіряє швидкість і, якщо цей комп'ютер достатньо швидкий, пропонує кращу модель, Ministral 3 8B (≈5,2 ГБ): її теж завантажує лише після «так» і використовує з наступного запуску (`src/gloxi/upgrade.py`, ADR 0008). Відповідь запам'ятовується в `speed-test.json` поруч із моделями. Вимкнути запуск: `[local] start_server = false` або `GLOXI_START_SERVER=0`.

Іконка тимчасова (знак Vilna).

**Сховище Flatpak Vilna** ([ADR 0024](../docs/adr/0024-vilna-flatpak-repository.md)). На Flathub Gloxi не подаємо: Flathub не приймає маніфестів і подань, зроблених AI. Замість цього CI імпортує той самий перевірений `gloxi.flatpak` у власне сховище OSTree, підписує його ключем GPG Vilna, а `tools/flatpak_repo.py` пише `io.github.stdenis1980.Gloxi.flatpakref` (встановити одним клацанням) і `vilna.flatpakrepo` (додати сховище). На кожному PR CI проходить увесь шлях з одноразовим ключем: сховище → `.flatpakref` → встановлення з перевіркою підпису → запуск. Справжнє сховище збирається лише за тегом, якщо в репозиторії є секрет `VILNA_FLATPAK_KEY` і змінна `VILNA_FLATPAK_URL`, і лежить в артефактах запуску; на bunny.net (`flatpak.vilnaos.com`) його викладає крок `publish` (`tools/upload_bunny.py`), лише коли Denys увімкнув змінну `VILNA_FLATPAK_PUBLISH` і схвалив запуск у середовищі `flatpak-publish`. Налаштування bunny.net — в ADR 0024.

**Випуск.** Пакет для тестувальників виходить на GitHub Releases. Щоб випустити версію:

1. Записати її в `pyproject.toml` (`version = "0.1.0"`) і першим `<release>` у `data/io.github.stdenis1980.Gloxi.metainfo.xml` (`version="0.1.0"`, дата, опис англійською й українською). Для попередніх версій у metainfo пишемо `~`: `0.2.0rc1` → `0.2.0~rc1`.
2. Поставити на main тег `gloxi-v0.1.0` і запушити його.

CI збирає пакет, проганяє ті самі перевірки, що й для PR, а `tools/release.py` звіряє тег, `pyproject.toml` і metainfo. Лише якщо все зійшлося, CI публікує `gloxi.flatpak` і його `gloxi.flatpak.sha256`. До 1.0 кожен випуск позначається як попередній (pre-release). Опис випуску береться з metainfo, тож пишемо його в одному місці.

### Мови інтерфейсу

Рядки інтерфейсу пишемо англійською в коді й перекладаємо через gettext (домен `gloxi`, [ADR 0009](../docs/adr/0009-languages.md)). Мову Gloxi бере з системи (`LANGUAGE`, `LANG`), як і всі застосунки GNOME; спробувати можна так: `LANGUAGE=uk uv run gloxi`.

- `po/gloxi.pot` — усі рядки; `po/<мова>.po` — переклади для 10 основних мов (uk, en як мова коду, es, pl, de, fr, it, ro, cs, lt). Їх можна редагувати в Poedit, згодом — у Weblate.
- У Gloxi 0.1 повна українська; каталоги інших мов уже заведено, перекладаємо поступово. З альфи всі основні мови мають бути повними.
- Новий рядок у коді: `_("...")` там, де текст показуємо, або `N_("...")` для сталих. Потім:

  ```sh
  python3 tools/i18n.py update    # оновити .pot і всі .po
  python3 tools/i18n.py compile   # зібрати .mo в src/gloxi/locale
  python3 tools/i18n.py check     # те саме перевіряє CI
  ```

  Плейсхолдери на кшталт `{host}` у перекладі мають лишатися такими самими: `check` це перевіряє.

### Заміри моделі

`gloxi-bench` проганяє набір із 30 тестових команд через локальну модель і пише звіт: скільки пройдено, швидкість, пам'ять сервера моделі. Як запускати і як обираємо модель за замовчуванням — у [`../docs/benchmarks.md`](../docs/benchmarks.md).

```sh
uv run pytest

python3 tools/i18n.py check
```

Тести не потребують справжньої моделі: `tests/fake_server.py` імітує API `llama-server`.
