# Gloxi

Gloxi («Глоксі», від *glaux* — сова Афіни) — AI-асистент Vilna.

Тут буде:

- системний сервіс Gloxi (працює під окремим користувачем, без прямого доступу до системи);
- маршрутизатор моделей: приватне й просте — локально (мала модель 1–3B), складне — у хмару;
- клієнт MCP, що підключає інструменти;
- окремо — прототип Gloxi як застосунку для звичайного Linux.

Усі дії Gloxi виконує лише через шлюз дозволів Herkos — див. [`../herkos/docs/permissions.md`](../herkos/docs/permissions.md).

## Стан

Каркас Gloxi 0.1 preview (див. [roadmap](../docs/roadmap.md), розд. 2.3–2.4): чат у терміналі з локальною моделлю через `llama-server` і маршрутизатор «локально / хмара за ключем користувача». Є вікно чату на GTK 4 / libadwaita, шлюз приватності для хмари і робота з файлами через Herkos-lite.

## Запуск для розробки

Покрокова інструкція для тестувальників — у [`../docs/getting-started.uk.md`](../docs/getting-started.uk.md) ([English](../docs/getting-started.md), [Español](../docs/getting-started.es.md)).

Потрібні Python ≥ 3.11 і [uv](https://docs.astral.sh/uv/).

1. Запустіть локальну модель через [llama.cpp](https://github.com/ggml-org/llama.cpp) ([ADR 0004](../docs/adr/0004-local-model-engine.md)). Підійде будь-яка мала instruct-модель у форматі GGUF. За замірами пропонуємо Qwen3 4B без «роздумів» ([ADR 0008](../docs/adr/0008-default-local-model.md)):

   ```sh
   llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --port 8080 -c 4096 \
     --chat-template-kwargs '{"enable_thinking":false}'
   ```

2. Поговоріть з Gloxi:

   ```sh
   cd gloxi
   uv sync
   uv run gloxi            # інтерактивний чат: /reset, /backup, /exit
   uv run gloxi ask "Що вмієш?"
   ```

Gloxi говорить з моделлю лише через OpenAI-сумісний API, тож замість `llama-server` можна вказати Ollama чи інший сервер: `--url http://127.0.0.1:11434/v1 --model qwen2.5:1.5b` або змінна `GLOXI_LOCAL_URL`.

### Вікно чату (GTK)

Вікно потребує PyGObject, GTK 4 і libadwaita із системи (у Flatpak вони прийдуть із рантайму GNOME). На Aeon усе ставимо в toolbox, на Fedora чи Ubuntu — прямо в систему:

```sh
# Fedora / toolbox на Aeon
sudo dnf install python3-gobject gtk4 libadwaita
# Ubuntu / Debian
sudo apt install python3-gi gir1.2-gtk-4.0 gir1.2-adw-1

cd gloxi
python3 -m venv --system-site-packages .venv-gtk
.venv-gtk/bin/pip install -e ../privacy-gateway -e ../mcp/files -e ../herkos -e ".[tools]"
.venv-gtk/bin/gloxi-gtk
```

Локальні пакети треба перелічити явно: pip не читає `[tool.uv.sources]` і шукав би їх на PyPI.

У заголовку вікна видно, чи ввімкнена хмара. Над кожною відповіддю написано, де її отримано: «На цьому комп'ютері» або «Хмара: host, з маскуванням». `/local` і `/cloud` на початку повідомлення працюють так само, як у терміналі. Кнопка «+» починає нову розмову. Мова інтерфейсу — мова системи (див. «Мови інтерфейсу»).

### Налаштування

`~/.config/gloxi/config.toml` (необов'язково):

```toml
[local]
url = "http://127.0.0.1:8080/v1"
model = "local"
timeout = 120

[cloud]                      # необов'язково: свій провайдер і свій ключ
url = "https://api.mistral.ai/v1"
model = "mistral-small-latest"
# api_key = "..."            # краще змінна GLOXI_CLOUD_API_KEY

[router]
mode = "auto"                # auto | local | cloud
cloud_allowed = false        # хмара вимкнена, доки користувач її не ввімкне
long_message_chars = 1500    # auto: довші повідомлення йдуть у хмару
mask_cloud = true            # шлюз приватності: маскувати особисті дані перед хмарою
```

Змінні середовища мають пріоритет над файлом: `GLOXI_LOCAL_URL`, `GLOXI_LOCAL_MODEL`, `GLOXI_LOCAL_TIMEOUT`, `GLOXI_CLOUD_URL`, `GLOXI_CLOUD_MODEL`, `GLOXI_CLOUD_API_KEY`, `GLOXI_CLOUD_ALLOWED`, `GLOXI_ROUTER_MODE`, `GLOXI_MASK_CLOUD`.

### Маршрутизатор

1. Без `cloud_allowed = true` і налаштованого `[cloud]` нічого не залишає комп'ютер.
2. `/local <текст>` або `/cloud <текст>` обирає модель для одного повідомлення.
3. `mode = "local"` або `"cloud"` (чи `--mode`) закріплює модель для всіх повідомлень.
4. `mode = "auto"`: прості повідомлення — локально, довші за `long_message_chars` — у хмару. Це стартове правило, його уточнимо на замірах.

Якщо локальна модель не відповідає, Gloxi **не** переходить у хмару сам, а показує помилку. Перед кожною відповіддю видно, куди пішло повідомлення: `[local]` або `[cloud: api.mistral.ai, masked]`.

### Шлюз приватності

Усе, що йде в хмару, спершу проходить через [шлюз приватності](../privacy-gateway/README.md) на цьому комп'ютері: пошта, телефони, номери документів і рахунків, ключі та паролі, підписані поля з ім'ям, датою народження чи адресою замінюються на `[EMAIL_1]`, `[PHONE_1]` тощо. Хмарна модель бачить лише замінники, а у відповіді Gloxi повертає справжні значення. В історії розмови лишаються справжні значення; замінники існують тільки в запиті до хмари і забуваються, коли починається нова розмова. Імена у вільному тексті шлюз поки не розпізнає.

`mask_cloud = false` вимикає маскування. Тоді біля кожної хмарної відповіді написано `not masked`.

### Файли через Herkos

Якщо запущено Herkos-lite (`herkos serve`, див. [`../herkos/README.md`](../herkos/README.md)), локальна модель отримує функції `files_list`, `files_search`, `files_read`, `files_create` і `files_write` для папок, які дозволено в налаштуваннях Herkos. Сам Gloxi файлів не торкається: кожен виклик іде в Herkos, той перевіряє рівень, за потреби питає людину у своєму вікні (з поясненням Gloxi, навіщо це), виконує дію і пише журнал. Відмову Gloxi отримує як звичайну відповідь і пояснює її людині. У чаті видно кожен виклик, наприклад `[files: read ~/Documents/plan.txt (done)]`.

- Видаляти файли Gloxi 0.1 не може: це R3, а Herkos-lite виконує лише R0–R2.
- Після читання чи пошуку розмова вважається «забрудненою» (у ній є чужий текст), тож Herkos-lite відхиляє зміни файлів до нової розмови (`/reset` або «Нова розмова»).
- Вміст файлів модель бачить лише всередині меж Keros (`herkos.keros.wrap`), які текст файлу не може закрити. Якщо Keros знаходить у файлі ознаки ін'єкції (наприклад, «ignore all previous instructions»), Gloxi показує попередження в чаті, а модель отримує примітку не виконувати цих вказівок.
- Вміст файлів не потрапляє в історію розмови, а хмарна модель функцій не отримує: файли лишаються на цьому комп'ютері.
- Модель має вміти викликати функції: `llama-server` потрібен із шаблоном чату, що знає інструменти (`--jinja`, у свіжих збірках так за замовчуванням).
- `[tools] enabled = false` або `GLOXI_TOOLS=0` вимикає функції. Без Herkos Gloxi просто розмовляє.

Для розробки Herkos ставиться разом із Gloxi (`uv sync`), а для пакета — як додаткова залежність `gloxi[tools]`.

### Копії: перша розмова

Якщо запущено Herkos-lite з інструментом «копії» ([`../mcp/backup/`](../mcp/backup/)), Gloxi на першому запуску (у терміналі й у вікні) питає про резервні копії за сценарієм [`backup/docs/design.md`](../backup/docs/design.md), розд. 2а: чи зберігати, що саме (з реальними розмірами папок), чи брати історію розмов, скільки місця (і які великі папки не брати, якщо не вміщається), куди і як часто. Це фіксований сценарій, а не модель: назви папок і розміри не потрапляють у жодну модель. Кожна зміна йде через Herkos, тож перший раз людина бачить його вікно.

- Місце зберігання і ключ відновлення — R3, тому останній крок людина робить сама: Gloxi дає готову команду `vilna-backup setup …` (згодом це буде вікно Herkos). Перша копія починається одразу після підтвердження аркуша.
- «Пізніше» — Gloxi спитає ще раз через тиждень, потім більше ні. `/backup` починає розмову будь-коли.
- Тексти перекладено, як і решту інтерфейсу (див. «Мови інтерфейсу»).

### Flatpak

Маніфест — [`flatpak/io.github.stdenis1980.Gloxi.yml`](flatpak/io.github.stdenis1980.Gloxi.yml): рантайм GNOME, бібліотеки Python у версіях з `uv.lock` (це перевіряє `tests/test_flatpak.py`), сам Gloxi, шлюз приватності, Herkos-lite та інструмент «файли». CI збирає пакет і перевіряє, що він запускається; готовий `gloxi.flatpak` лежить в артефактах запуску.

```sh
flatpak-builder --user --install --force-clean build flatpak/io.github.stdenis1980.Gloxi.yml
flatpak run io.github.stdenis1980.Gloxi                      # вікно
flatpak run --command=gloxi io.github.stdenis1980.Gloxi      # термінал
```

У пісочниці Gloxi має мережу (локальна модель на `127.0.0.1` і хмара, якщо її ввімкнено) і більше нічого: доступу до файлів немає. Herkos-lite і інструмент «файли» лежать у тому ж пакеті; Gloxi сам запускає Herkos окремим процесом (`src/gloxi/herkos_local.py`), і сокет лишається всередині пісочниці. Теки, з якими Gloxi може працювати, людина обирає кнопкою з текою в заголовку вікна: відкривається системне вікно вибору (портал документів), і лише обрані теки стають видимими й потрапляють у `allowed_roots` Herkos. Поки тек не обрано, інструментів немає. Це слабше, ніж у Vilna, де Herkos — системна служба поза сеансом людини; опис пакета про це каже. Налаштування Gloxi лежать у `~/.var/app/io.github.stdenis1980.Gloxi/config/gloxi/config.toml`, Herkos — поруч, у `config/herkos/config.toml`.

У пакеті є `llama-server` (llama.cpp b12048, CPU і Vulkan). Якщо на `[local] url` ніхто не відповідає, Gloxi запускає його сам, лише на `127.0.0.1` ([ADR 0004](../docs/adr/0004-local-model-engine.md)). Моделі в пакеті немає: на першому запуску Gloxi питає, чи завантажити Qwen3 4B (≈2,5 ГБ, [ADR 0008](../docs/adr/0008-default-local-model.md)), і без «так» нічого не завантажує. Файл перевіряється за SHA-256 з `src/gloxi/engine.py` і лежить у `~/.var/app/io.github.stdenis1980.Gloxi/data/gloxi/models`; перерване завантаження продовжується. Вимкнути запуск: `[local] start_server = false` або `GLOXI_START_SERVER=0`.

Іконка тимчасова (знак Vilna), знімків екрана для Flathub ще немає.

### Мови інтерфейсу

Рядки інтерфейсу пишемо англійською в коді й перекладаємо через gettext (домен `gloxi`, [ADR 0009](../docs/adr/0009-languages.md)). Мову Gloxi бере з системи (`LANGUAGE`, `LANG`), як і всі застосунки GNOME; спробувати можна так: `LANGUAGE=uk uv run gloxi`.

- `po/gloxi.pot` — усі рядки; `po/<мова>.po` — переклади для 10 основних мов (uk, en як мова коду, es, pl, de, fr, it, ro, cs, lt). Їх можна редагувати в Poedit, згодом — у Weblate.
- У Gloxi 0.1 повна українська; каталоги інших мов уже заведено, перекладаємо поступово. З альфи всі основні мови мають бути повними.
- Новий рядок у коді: `_("...")` там, де текст показуємо, або `N_("...")` для сталих. Потім:

  ```sh
  python3 tools/i18n.py update    # оновити .pot і всі .po
  python3 tools/i18n.py compile   # зібрати .mo в src/gloxi/locale
  python3 tools/i18n.py check     # те саме перевіряє CI
  ```

  Плейсхолдери на кшталт `{host}` у перекладі мають лишатися такими самими: `check` це перевіряє.

### Заміри моделі

`gloxi-bench` проганяє набір із 30 тестових команд через локальну модель і пише звіт: скільки пройдено, швидкість, пам'ять сервера моделі. Як запускати і як обираємо модель за замовчуванням — у [`../docs/benchmarks.md`](../docs/benchmarks.md).

### Тести і перевірки

```sh
uv run pytest
uv run ruff check . && uv run ruff format --check .
python3 tools/i18n.py check
```

Тести не потребують справжньої моделі: `tests/fake_server.py` імітує API `llama-server`.

## Структура

| Модуль | Що робить |
| --- | --- |
| `gloxi/config.py` | Налаштування: типові значення, файл TOML, змінні середовища |
| `gloxi/engine.py` | Вбудована модель: завантаження за згодою з перевіркою SHA-256, запуск `llama-server` на 127.0.0.1 |
| `gloxi/i18n.py` | Мова інтерфейсу: gettext, каталоги в `gloxi/locale` |
| `gloxi/llm.py` | Клієнт OpenAI-сумісного API (звичайна і потокова відповідь) — спільний для локальної моделі й хмари |
| `gloxi/router.py` | Маршрутизатор: куди йде повідомлення (локально чи в хмару) і чому; маскування перед хмарою через `CloudGuard` |
| `gloxi/privacy.py` | Підключає шлюз приватності (`privacy_gateway.Masker`) до маршрутизатора |
| `gloxi/chat.py` | Розмова: системна підказка й історія, обрізана до останніх реплік |
| `gloxi/gui/controller.py` | Логіка вікна без GTK: маршрут, потокова відповідь у фоні, помилки (тестується без дисплея) |
| `gloxi/gui/window.py` | Вікно GTK 4 / libadwaita і застосунок `io.github.stdenis1980.Gloxi` |
| `gloxi/cli.py` | Чат у терміналі (інструмент розробника; вікно GTK використовуватиме ту саму `Conversation`) |
