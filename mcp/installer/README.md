# vilna-mcp-installer

MCP-сервер установника Vilna ([`image/docs/installer.md`](../../image/docs/installer.md), розд. 2), формат плану встановлення і **валідатор плану** (розд. 4–5). Валідатор не залежить від моделі: ним користуються розмова з Gloxi, звичайний майстер і екран підтвердження Herkos.

Сервер **читає** комп'ютер і **змінює лише план**. Інструмента «стерти», «розмітити», «підключитися» чи «встановити» немає: стирання — лише наслідок плану, який людина підтвердила на екрані Herkos.

| Інструмент | Що робить |
| --- | --- |
| `hardware_describe` | Процесор, пам'ять, UEFI, Secure Boot, TPM |
| `locale_list`, `keyboard_list`, `timezone_list` | Мови Vilna, розкладки xkb, часові пояси |
| `network_scan` | Мережі Wi‑Fi поруч (NetworkManager) і чи є кабель |
| `disks_survey` | Диски (стабільний id з `/dev/disk/by-id`), розділи (PARTUUID), знайдені ОС, шифрування, вільне місце, відбиток набору дисків |
| `plan_get`, `plan_validate` | План і його перевірка: чого бракує, що блокує, кожна зміна диска окремим рядком |
| `plan_set_languages`, `plan_set_network`, `plan_set_disk`, `plan_set_encryption`, `plan_set_user`, `plan_set_time` | Записати рішення в план |

Назви — з `_` замість `.` з installer.md, бо виклик функцій у стилі OpenAI крапок не приймає.

## Хто що ставить у плані

- **Gloxi** (через ці інструменти): мови, розкладки, мережа, диск і що з ним робити, спосіб шифрування, ім'я, логін, назва комп'ютера, час.
- **Лише людина**, у редакторі розділів класичного майстра: розділи ручної розмітки (`disk.partitions`, `plan.set_partitions`, див. нижче).
- **Лише людина**, у захищених полях установника або на екрані Herkos: що пароль Wi‑Fi, пароль користувача чи фразу диска введено (`"entered"`), що ключ відновлення збережено, що резервна копія є, і `confirmed_by_user`. У плані немає жодного пароля чи ключа, лише позначка; валідатор відхиляє план, де замість неї є щось інше.
- **Незмінне**: `privacy.cloud = "disabled"` під час встановлення.

Будь-яка зміна знімає `confirmed_by_user`: після зміни людина дивиться план знову.

## Правила валідатора

Розд. 5 installer.md: розділ із даними стирається лише за `replace` або явного переліку, і кожен такий розділ — окремий рядок у `changes`; файли з розділу, що стирається, — лише з копією на інший диск; зменшення розділу Windows — лише з призупиненим BitLocker, перевіреною файловою системою і підтвердженою копією; RAID, LVM і невідомі файлові системи — лише ручна розмітка; якщо набір дисків змінився після огляду (`disk.survey` — відбиток), план недійсний; шифрування — лише з підтвердженим ключем відновлення. Також: не на флешку, з якої запущено Vilna; щонайменше 40 ГіБ; логін і назва комп'ютера за правилами системи.

## Ручна розмітка

`disk.layout = "manual"` потребує `disk.partitions` — списку з редактора розділів (до 8 пунктів):

```json
[{"use": "efi", "partition": "<PARTUUID>", "format": false},
 {"use": "system", "size": 107374182400},
 {"use": "home", "partition": "<PARTUUID>", "format": true}]
```

`use` — `efi`, `system`, `home` або `swap`; пункт — або наявний розділ цільового диска (`partition`, `format`), або новий у найбільшому вільному місці (`size` у байтах). Валідатор вимагає рівно один EFI і одну систему; система (≥ 40 ГіБ) і підкачка завжди форматуються; EFI без форматування — лише справжній розділ EFI (≥ 256 МіБ); домашні теки без форматування — лише незашифрований розділ Linux; кожен розділ — один раз; нові розділи мають уміститися. У `changes` кожен розділ диска — `erase`, `use` (використано без форматування, файли лишаються), `keep` (не обраний, лишається як є) або `create`, з полем `use`. Якщо на диску лишається Windows із BitLocker, у `warnings` є `bitlocker_recovery_key`: Windows може попросити ключ відновлення, бо в спільному розділі EFI з'являється новий завантажувач. Повторний `plan_set_disk` того самого диска з `manual` зберігає вибір редактора, інший диск чи спосіб його знімає.

Альфа — простий шлях (розд. 8): `replace` і `manual`. `alongside`, `free_space` і перенесення файлів валідатор перевіряє вже зараз (`--stage beta`), але в альфі відхиляє як `later_stage`.

```sh
uv run vilna-mcp-installer --plan /tmp/plan.json --demo windows   # синтетичний комп'ютер
uv run vilna-plan-check /tmp/plan.json --demo windows              # звіт валідатора, код 0/1/2
```

Під час встановлення сервер запускає установник (`vilna_installer.conversation`), а не Gloxi; маніфесту Herkos у нього немає, щоб у встановленій системі Gloxi його не бачив. Режим встановлення Herkos і екран підтвердження R4 — окрема робота.
