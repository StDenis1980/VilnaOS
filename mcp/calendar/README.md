# vilna-mcp-calendar

MCP-сервер «календар» для Gloxi ([ADR 0023](../../docs/adr/0023-gloxi-calendar-settings-hotkey.md)): список календарів, події за період, пошук подій, а з пункту 27 плану альфи ще й запис: створити, змінити й видалити подію. Джерело — сховище календарів GNOME, Evolution Data Server (рішення Denys 2026-11-09): туди потрапляють календарі з «Календаря» GNOME і облікових записів GNOME (Google, Nextcloud, Microsoft, CalDAV).

- **Період рахує сервер**, а не модель: `list_events` бере слово (`today`, `tomorrow`, `this_week`, `next_week`, `this_month`, `next_month`) або дати ISO 8601 (`start`, `end`, до 366 днів). Час — у поясі людини; якщо в події свій пояс, він іде в `event_timezone`.
- Повторювані події розгортає EDS. Межі: до 200 подій за запит (`truncated`), назва й місце до 500 символів, опис до 2000; з одного календаря читається не більше 5000 повторів.
- Показуються лише календарі, увімкнені в GNOME; приховані — тільки якщо їх назвати в `calendars`.
- Кожна подія в результаті має `id` і `calendar_id`: за ними її можна змінити або видалити.

## Запис

| Операція | Що робить | Рівень у Herkos |
| --- | --- | --- |
| `create_event` | Нова подія: `title`, `start` і, за бажання, `end`, `location`, `description`, `calendar`. Дата без часу (`2027-03-05`) — подія на весь день, `days` — на скільки днів. Без `end` подія триває годину. Без `calendar` — у календар за замовчуванням GNOME | R2 |
| `update_event` | Змінює лише те, що назвали. Новий `start` зберігає тривалість; дата без часу переносить подію на той день о тій самій годині | R2 |
| `delete_event` | Видаляє подію | R3, як видалення файлу |
| `restore` | Повертає подію такою, якою вона була до зміни. Її викликає Herkos, коли людина натискає «Скасувати» | R2 |

- **Лише прості події, у яких немає інших людей.** Повторювану подію (яке саме повторення?) і зустріч із запрошеними (зміна надіслала б їм лист, а це R4) сервер не змінює і просить зробити це в програмі календаря. Створювати повтори й запрошувати людей Gloxi поки не вміє.
- **Змінюються лише названі властивості.** Нагадування, категорії й усе інше в події лишається, як було; лічильник `SEQUENCE` росте, щоб сервер CalDAV прийняв зміну.
- **Кожну зміну можна скасувати.** Перед зміною сервер зберігає подію цілком (iCalendar) у `$XDG_STATE_HOME/vilna-mcp-calendar/undo/` (тека 0700, файли 0600, до 1000 записів і 90 днів, подія до 256 КБ) і повертає Herkos `undo_arguments` з одноразовим токеном. Скасування теж повертає токен, тож його можна скасувати.
- Час без поясу — у поясі людини; подія з часом записується в UTC (той самий момент, кожен бачить його у своєму поясі), подія на весь день — датами.
- Межі ті самі, що й для читання: назва й місце до 500 символів, опис до 2000, тривалість до 366 днів, роки 1970–2200.
- Після читання подій розмова «забруднена» (чужий текст), тож запис стає R3: Herkos питає щоразу, лише «один раз», і показує точно, що буде записано. Видалення (R3) робить лише системний Herkos; Herkos-lite у Flatpak його не виконує.

- Усе, що повертає сервер, — чужий текст: Herkos позначає його для Keros (маніфест `herkos/src/herkos/manifests/org.vilna.mcp.calendar.toml`), а шлюз приватності маскує перед хмарою.

```sh
uv run vilna-mcp-calendar          # календарі EDS (потрібні PyGObject і typelib ECal 2.0)
uv run vilna-mcp-calendar --demo   # два вигадані календарі в пам'яті, для тестів і показу
```

Транспорт — MCP через stdio (JSON-RPC 2.0, одне повідомлення на рядок). Ліцензія Apache-2.0 (див. [`../LICENSE`](../LICENSE)).
