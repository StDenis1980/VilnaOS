# 0017. Сторонні MCP-сервери: як Gloxi працює з іншими програмами

- Стан: Прийнято (Denys, 2026-11-05)
- Дата: 2026-11-05
- Пов'язано: [roadmap](../roadmap.md), [ADR 0005](0005-gloxi-herkos-channel.md), [ADR 0011](0011-default-office-suite.md), [ADR 0012](0012-recommended-apps-and-install-via-gloxi.md), [ADR 0013](0013-herkos-rust.md), [ADR 0016](0016-gloxi-for-code-editors.md), [`permissions.md`](../../herkos/docs/permissions.md) розд. 4.1, 9.5, 11, [`protocol.md`](../../herkos/docs/protocol.md) розд. 5

## Контекст

Denys питає, чи Gloxi може працювати з іншими програмами в системі, які мають MCP-сервер. Таких програм стає більше, і серед них наші ж: усі п'ять програм Tinta Office уже мають MCP-сервер (`wordcraft-cli mcp`, `gridcraft-cli mcp`, `pdfcraft-cli mcp`, `deckcraft-cli mcp`, `ibercorreo-cli mcp`), а Tinta за [ADR 0011](0011-default-office-suite.md) стає офісом Vilna.

Що є зараз (Gloxi 0.1):

- Gloxi викликає лише два вбудовані інструменти, «файли» (`org.vilna.mcp.files`) і «копії» (`org.vilna.mcp.backup`). Їх запускає Herkos (`herkos/src/herkos/cli.py`), а не Gloxi; список інструментів для моделі задано в коді Gloxi (`gloxi/src/gloxi/tools.py`).
- Маніфести з рівнями ризику постачаються разом із Herkos. Інструмент без маніфесту Herkos-lite **відхиляє** (`denied_unknown`, `herkos/src/herkos/gate.py`). Це суворіше, ніж каже `permissions.md` розд. 4.1 (R3 для читання, R4 для решти); розбіжність закриваємо цим ADR: у Herkos-lite відмова лишається (сторонніх серверів у ньому немає), рівні розд. 4.1 — у `herkosd`.
- Немає способу знайти сторонній сервер, додати його чи вимкнути.
- У Flatpak Herkos-lite працює в тій самій пісочниці, що й Gloxi. Запустити звідти програму на хості можна лише через `flatpak-spawn --host`, а це майже повний вихід з пісочниці. Тому з Flatpak-версії Gloxi безпечно під'єднати чужу програму не вийде; це можливо лише із системним `herkosd` ([ADR 0013](0013-herkos-rust.md)), який уже сам запускає інструменти від імені людини через шаблонні юніти systemd.

Тобто відповідь на питання сьогодні: **ні, лише вбудовані «файли» й «копії»**.

## Рішення

### 1. Хто запускає і як

- Сторонні сервери запускає **лише системний `herkosd`**, як і вбудовані (permissions.md 9.5). Gloxi їх не бачить напряму, лише через Herkos.
- Транспорт — **stdio**: `herkosd` запускає процес у шаблонному юніті `vilna-mcp-ext@<id>.service` від імені людини, з обмеженнями systemd (`ProtectSystem=strict`, `PrivateNetwork=yes`, якщо маніфест не каже `egress`, лише дозволені теки). Програма з Flatpak запускається через `flatpak run --command=<cli> <app-id> mcp`, тобто у власній пісочниці.
- Мережевий транспорт MCP (Streamable HTTP на `127.0.0.1`) — пізніше і лише з ключем, якщо знайдеться програма, що вміє тільки так.

### 2. Як Herkos дізнається про сервер

- **Каталог Vilna.** Пакет `herkos-manifests` (OBS, підписаний ключем пакетів Vilna) містить маніфест для кожної перевіреної програми: як запустити (`launch`), операції, рівні, `resource_args`, `egress`. Рівні задає Herkos, а не автор програми (protocol.md розд. 5). Це закриває відкрите питання «хто підписує маніфести» (permissions.md розд. 11): у каталозі — Vilna, через підпис пакета.
- **Вручну.** Людина може додати будь-який сервер у налаштуваннях Gloxi («Програми для Gloxi → Додати»). Додавання — дія R4 з показом точної команди. Такий сервер працює з найсуворішими рівнями розд. 4.1: R3 для операцій з `readOnlyHint`, R4 для решти. Анотації можуть рівень лише підвищити.
- Будь-який сервер можна вимкнути одним перемикачем; вимкнений не запускається.

### 3. Що Herkos перевіряє

- **Список інструментів зафіксовано.** Під час додавання Herkos запам'ятовує хеш відповіді `tools/list` (назви, описи, схеми). Якщо програма після оновлення змінила список чи опис, нові й змінені операції працюють як без маніфесту, доки людина їх не прийме (захист від підміни інструмента після схвалення).
- **Описи інструментів — зовнішній вміст.** Keros перевіряє їх на prompt injection до того, як вони потраплять у модель; підозрілий опис — інструмент не показується, людина бачить чому.
- **Відповіді — зовнішній вміст** (`returns_external`, сеанс стає `tainted`, permissions.md розд. 6), як і для «файлів».
- **Межі ресурсів.** Шляхи в `resource_args` мусять бути в теках, які людина дозволила, як для «файлів». Програми Tinta вже мають власні межі (`--root` у PdfCraft, список дозволених команд у GridCraft), і `launch` їх використовує.
- **Журнал Mitos** пише кожен виклик стороннього сервера, як і вбудованих.

### 4. Що змінюється в Gloxi

- Новий метод протоколу `herkos.tools`: Herkos віддає Gloxi список увімкнених інструментів зі схемами (лише те, що пройшло перевірки). Gloxi перестає задавати список у коді.
- Мала локальна модель (Qwen3 4B) губиться, коли інструментів багато. Тому Gloxi дає моделі лише інструменти програм, увімкнених людиною, і лише ті, що стосуються запиту (спершу за назвою програми в запиті, далі — за коротким описом).
- Шлюз приватності не змінюється: дані зі сторонніх інструментів ідуть у хмару лише через нього і лише якщо хмару ввімкнено.

### 5. У яку версію

| Коли | Що |
| --- | --- |
| **Gloxi 0.2** (лютий — березень 2027) | Лише підготовка, без сторонніх серверів: метод `herkos.tools`, Gloxi бере список інструментів від Herkos, поле `launch` у маніфесті (Herkos-lite запускає вбудовані інструменти за ним, а не за кодом). Herkos-lite і далі відхиляє інструмент без маніфесту: рівні розд. 4.1 для таких серверів вмикає `herkosd` на етапі 2. 0.2 і так повна (календар, налаштування GNOME, ендпоінт для редакторів), а з Flatpak сторонні програми безпечно не запустити. |
| **Етап 2, образ Vilna** (квітень — вересень 2027) | Каталог `herkos-manifests` і юніт `vilna-mcp-ext@`. Перші — програми Tinta Office (у них MCP уже є): «зроби з цієї таблиці звіт у документі», «знайди в пошті рахунок і збережи PDF». |
| **Альфа** (жовтень 2027 — березень 2028) | Додавання будь-якого сервера вручну, фіксація `tools/list`, Keros для описів, SDK для сторонніх розробників (маніфест + як потрапити в каталог). Разом із варіантом Б ADR 0016 (MCP-сервер Gloxi для чужих агентів). |

## Наслідки

- Gloxi отримує доступ до цілих програм, а не лише до файлів, і всі дії йдуть через Herkos з тими самими рівнями й журналом.
- Ціна: кожна програма в каталозі — маніфест, який треба написати й перевірити; кожне оновлення програми може змінити список інструментів.
- На чужих дистрибутивах (лише Flatpak Gloxi) сторонніх програм не буде; чесно кажемо це в описі Gloxi.
- Для Tinta: потрібен стабільний набір MCP-операцій у кожній програмі й спосіб обмежити теки під час запуску. Запит у tintaoffice-web — після погодження цього ADR (issue з міткою `from-neighbor`).

## Розглянуті варіанти

- **Gloxi запускає сервери сам** (як Claude Desktop чи Cursor, файл зі списком команд). Просто, але повз Herkos: модель із доступом до чужої програми без рівнів, підтверджень і журналу. Ні.
- **`flatpak-spawn --host` з Flatpak Gloxi вже в 0.2.** Дає сторонні програми на будь-якому дистрибутиві, але Gloxi-пісочниця фактично зникає. Ні.
- **Автоматичний пошук усіх MCP-серверів у системі** (сканувати Flatpak і `PATH`). Немає стандартного способу оголосити MCP-сервер, і сервер без маніфесту все одно мав би найсуворіші рівні. Лише каталог і ручне додавання.
