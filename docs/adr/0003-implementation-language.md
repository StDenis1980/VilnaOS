# 0003. Мова реалізації: Python для Gloxi 0.1, Rust для системного Herkos

- Стан: Прийнято
- Дата: 2026-11-01
- Пов'язано: [roadmap](../roadmap.md) розд. 2.1 (Р3), [`herkos/docs/permissions.md`](../../herkos/docs/permissions.md)

## Контекст

До Gloxi 0.1 preview (кінець січня 2027) мало часу, і працює поки одна людина. Треба швидко зібрати чат, маршрутизатор моделей, шлюз приватності й Herkos-lite. Водночас системний Herkos (етап 2) — межа безпеки, що працює з правами, яких немає в Gloxi, і там помилки пам'яті неприпустимі.

## Рішення

- **Gloxi 0.1, включно з Herkos-lite, — Python** (≥ 3.11). Інтерфейс — GTK 4 / libadwaita через PyGObject. Залежності мінімальні: `httpx` для HTTP, стандартна бібліотека для решти.
- **Системний Herkos на етапі 2 — Rust.**
- Стабільними тримаємо **не код, а контракти**: протокол Gloxi ↔ Herkos ([0005](0005-gloxi-herkos-channel.md)), формат запиту дії і маніфести інструментів (permissions.md). Herkos-lite на Python — еталонна реалізація цих контрактів, і тести до неї пишемо так, щоб їх можна було прогнати проти Rust-версії.
- Інструменти — окремі MCP-сервери; мова кожного обирається окремо (для файлів у 0.1 — Python).

## Наслідки

- Найшвидший шлях до січневого випуску; PyGObject і Python є в GNOME Flatpak-рантаймі.
- Herkos-lite на Python у сеансі користувача **не дає гарантій ізоляції**; це прямо сказано в описі preview.
- На етапі 2 Herkos переписуємо; витрати на це приймаємо свідомо.
- Інструменти якості: `ruff` (лінтер і форматування), `pytest`, `uv` для середовища розробки.

## Розглянуті варіанти

- **Rust одразу для всього.** Безпечніше, але з невеликою командою січень недосяжний, а GTK-інтерфейс на Rust повільніше писати.
- **Go для Herkos.** Простіший за Rust, але має збирач сміття і більший рантайм; Rust ближчий до системних компонентів openSUSE і краще підходить для малого привілейованого сервісу.
- **TypeScript / Electron для Gloxi.** Важкий для мінімального заліза (8 ГБ RAM, з яких частина під локальну модель) і чужий для GNOME.
