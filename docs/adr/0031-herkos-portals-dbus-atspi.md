# 0031. Herkos і стільниця: маніфести D-Bus із фільтром шини, дозволи порталів Flatpak, AT-SPI із захищеними вікнами

- Стан: Запропоновано
- Дата: 2026-11-20
- Пов'язано: [roadmap](../roadmap.md) розд. 4 («Flatpak portals, D-Bus- і AT-SPI-маніфести для GNOME»), [ADR 0002](0002-first-desktop.md) (спершу GNOME), [ADR 0013](0013-herkos-rust.md) (системний `herkosd`), [ADR 0017](0017-third-party-mcp-servers.md) (маніфести й юніти інструментів), [ADR 0023](0023-gloxi-calendar-settings-hotkey.md) (`undo_arguments`), [ADR 0029](0029-herkos-real-input.md) (вікна Herkos лише від справжнього натискання), [`permissions.md`](../../herkos/docs/permissions.md) розд. 4, 6, 9.3, 9.4, [`protocol.md`](../../herkos/docs/protocol.md) розд. 5

## Контекст

Пункт 30 переліку робіт до альфи Blavet. `permissions.md` обіцяє три речі, яких у коді досі немає:

1. **D-Bus** (розд. 9.4): «для кожного D-Bus-інтерфейсу, який використовує Herkos, є маніфест із рівнем ризику для кожного методу; невідомі методи заборонено». Зараз інструменти «налаштування» і «календар» ходять на сесійну шину людини самі, і що саме вони там викликають, видно лише з їхнього коду. Процес під uid людини, який дістався до сесійної шини, може викликати будь-що: від `org.gnome.Shell.Screenshot` до `org.freedesktop.systemd1` сеансу.
2. **Портали Flatpak** (розд. 9.3): «Herkos читає й змінює дозволи інших Flatpak-програм через сховище дозволів порталу лише як дію R3». Інструмента для цього немає.
3. **AT-SPI** (розд. 9.4): «дії через нього щонайменше R2, натискання в діалогах безпеки (polkit, Herkos, менеджер паролів) заборонене; прочитаний текст — зовнішній вміст для Keros». Інструмента теж немає.

Обмеження: усе під uid людини має однаковий доступ до її сесійної шини й шини доступності; маніфест — це те, що каже Herkos, а не те, що може процес. ADR 0029 уже закрив зворотний напрям (чужа програма не натисне кнопок Herkos через AT-SPI).

## Рішення

### 1. Маніфест D-Bus: ключ `dbus` в операції і фільтр шини

Операція маніфесту може назвати виклики D-Bus, які вона робить:

```toml
[operations.notify]
level = "R1"
summary = "Show a notification from Gloxi"
dbus = [
  { bus = "session", name = "org.freedesktop.Notifications", path = "/org/freedesktop/Notifications", call = "org.freedesktop.Notifications.Notify" },
]
```

- `bus` — `session` або `system`; `name` — відома назва на шині (може закінчуватися на `.*`: `org.mpris.MediaPlayer2.*`, усі програвачі); `path` — шлях об'єкта (може закінчуватися на `/*`); `call` — `інтерфейс.Метод`, без зірочок.
- Рівень методу — рівень його операції. Заборонена операція (`forbidden`) викликів не має.
- Перевірка однакова в Python і Rust: невідомі ключі, неправильні назви, понад 16 викликів на операцію чи 64 на маніфест — помилка, інструмент лишається невідомим.
- Програма з Flatpak (`[launch] flatpak`) `dbus` не має: її шину вже обмежує сам Flatpak.

**Фільтр.** Для інструмента з `dbus` системний `herkosd` не довіряє його коду. Юніт інструмента (`vilna-mcp-<назва>@<uid>`) не бачить справжніх шин людини: `TemporaryFileSystem=/run/user:ro` ховає її `/run/user/<uid>` (сесійну шину, менеджер systemd користувача, Wayland), `/run/dbus` недоступна, а `PrivateNetwork=yes` закриває й абстрактні сокети. Говорить він лише з `xdg-dbus-proxy` (той самий фільтр, що й у Flatpak) з `--filter` і `--call` для викликів із маніфесту. Проксі — окремий юніт `vilna-dbus-proxy-<назва>@<uid>`, який systemd запускає як залежність інструмента (сам `herkos` запускати його не може, правило polkit). Він виконує `herkosd dbus-proxy`: ця команда бере маніфест, вбудований у `herkosd`, а не файл з диска, і передає `xdg-dbus-proxy` по одному `--call` на кожен рядок `dbus`; сокети — у `/run/herkos-bus/<uid>/<назва>/` (`session.bus`, `system.bus`). Невідомий метод проксі відкидає (`AccessDenied`), а назву, якої немає в маніфесті, не показує зовсім (`ServiceUnknown`), навіть якщо код інструмента зламано. Herkos-lite фільтра не має і таких інструментів не запускає (у маніфестах немає `module`).

Що перевірено: у контейнері з `dbus-daemon` і `xdg-dbus-proxy` 0.1.5 виклик із маніфесту проходить, а інший метод того самого об'єкта, той самий метод на іншому шляху, `Introspect` і чужі служби (знімок екрана GNOME Shell) — ні (`mcp/desktop/tests/test_proxy.py`).

### 2. Інструмент «стільниця» (`org.vilna.mcp.desktop`) — перші маніфести D-Bus для GNOME

`vilna-mcp-desktop` (пакет `vilna-mcp-desktop`, [`mcp/desktop/`](../../mcp/desktop/)):

| Операція | Виклик D-Bus | Рівень |
| --- | --- | --- |
| `battery` | UPower: `Properties.GetAll` на `DisplayDevice` (системна шина) | R0 |
| `notify` | `org.freedesktop.Notifications.Notify`, від імені «Gloxi», без дій і звуків | R1 |
| `media_status` | MPRIS: `Properties.GetAll` (`PlaybackStatus`, `Metadata`) усіх програвачів | R1, зовнішній вміст (назви треків) |
| `media_control` | MPRIS: `PlayPause`, `Play`, `Pause`, `Next`, `Previous`, `Stop` | R1 |
| `lock_screen` | `org.gnome.ScreenSaver.Lock` | R1 |

Заборонено (і тому без `dbus`): знімки й запис екрана (`org.gnome.Shell.Screenshot`, `Screencast`), `Eval` GNOME Shell, керування службами systemd сеансу, вимкнення й перезавантаження. Решта GNOME через D-Bus додається сюди ж, операція за операцією.

### 3. Дозволи порталів Flatpak (`org.vilna.mcp.portals`)

`vilna-mcp-portals` говорить зі сховищем дозволів порталів (`org.freedesktop.impl.portal.PermissionStore`: `Lookup`, `SetPermission`, для скасування ще `DeletePermission`) лише про сім дозволів, які людина бачить у «Налаштуваннях → Програми»:

| Дозвіл | Таблиця / id | Значення |
| --- | --- | --- |
| камера, мікрофон, динаміки | `devices` / `camera`, `microphone`, `speakers` | `yes`, `no`, `ask` |
| місцезнаходження | `location` / `location` | точність (`NONE` … `EXACT`) і час |
| сповіщення | `notifications` / `notification` | `yes`, `no` |
| фонова робота | `background` / `background` | `yes`, `no`, `ask` |
| знімки екрана | `screenshot` / `screenshot` | `yes`, `no` |

- `list` (R1): дозволи всіх програм або однієї.
- `revoke` (R2, `undoable`): забрати дозвіл. Повертає `undo_arguments` з попереднім значенням.
- `grant` (R3): дати дозвіл. Herkos питає щоразу або на сеанс, як велить розд. 9.3.
- `restore` (R3): повернути значення з `undo_arguments` (а дозвіл, якого раніше не було, — забути, щоб портал знову спитав людину). Теж R3, бо повернення забраного — це знову «дати», і Gloxi може викликати `restore` сам.

Відмінність від тексту розд. 9.3 («читає й змінює лише як R3»): читання — R1, забрати дозвіл — R2 зі скасуванням. Забрати дозвіл лише зменшує доступ програми і повертається за одну дію; питати про це так само суворо, як про «дати», означає, що Gloxi не допоможе там, де людина хоче захиститися. `permissions.md` оновлено.

Статичні дозволи Flatpak (`flatpak override`: файли, мережа, пристрої) інструмент поки не змінює: це окрема операція з R3 і показом точного дозволу, наступний крок. Журнал рішень самого порталу (коли портал питає людину сам, Herkos не питає вдруге, але записує відповідь) з'явиться разом із першим інструментом, що йде через портал (вибір файлу для Gloxi, `FileChooser`): зараз жоден інструмент Herkos порталом не користується.

### 4. AT-SPI (`org.vilna.mcp.atspi`)

`vilna-mcp-atspi` читає вікна інших програм і діє в них через шину доступності:

| Операція | Що | Рівень |
| --- | --- | --- |
| `list_windows` | програми й їхні вікна | R1, зовнішній вміст (назви вікон) |
| `read_window` | дерево елементів вікна: роль, назва, текст, стан, id | R1, зовнішній вміст |
| `describe` | що саме буде натиснуто чи змінено: програма, вікно, роль, назва | R0, лише для `preview` |
| `activate` | натиснути кнопку, пункт меню, перемикач (дія AT-SPI) | R2 → R3 (не скасовується) |
| `set_text` | замінити текст у полі введення | R2, `undoable` |
| `restore` | повернути попередній текст поля | R2 |

- **Що бачить людина.** `activate` і `set_text` мають `preview = "describe"`: системний `herkosd` показує в діалозі програму (за процесом, а не за назвою, яку програма каже про себе), назву вікна й кнопку чи поле. Елемент задано id з `read_window` і назвою, яку Gloxi бачив: якщо вікно змінилося й назва вже інша, дія не виконується.
- **Захищені програми** ніколи не з'являються в `list_windows`, їх не читають і в них не натискають. Програму впізнаємо за процесом, який віддає шина доступності (`GetConnectionUnixProcessID`), а не за назвою: файл програми (`/proc/<pid>/exe`), рядок запуску і для Flatpak — id з cgroup (`app-flatpak-<id>-….scope`). Процес, якого не вдалося впізнати, вважаємо захищеним. Видати себе за захищену програму можна, але це лише сховає програму від Gloxi.
  - безпека й секрети: GNOME Shell (вікна polkit, екран блокування, запити паролів), `gcr-prompter`, агенти polkit, GDM, Initial Setup, `pinentry`, `ssh-askpass`, Паролі й ключі (Seahorse), Secrets, KeePassXC, Bitwarden, 1Password, Proton Pass, Authenticator;
  - власні вікна Vilna: Herkos (вікно підтвердження, агент, «Дозволи»), Gloxi, установник, «Копії», — у кожного є свій інструмент через Herkos;
  - адміністрування, де клік може обійти Herkos: «Налаштування» GNOME, «Програми» (GNOME Software, Myrlyn, YaST), Flatseal, Диски, GParted, dconf Editor, менеджери розширень, термінали (GNOME Console, Ptyxis, GNOME Terminal, Konsole, xterm, Alacritty, kitty, WezTerm, foot, Tilix, Terminator, Ghostty).
- **Паролі й буфер обміну.** Текст поля з роллю «пароль» не читається і не змінюється ніде. Дій AT-SPI з буфером обміну (`clipboard.*`, «вставити», «копіювати», «вирізати») інструмент не показує й не виконує: вставка могла б перенести пароль, який людина скопіювала, у форму на сайті.
- **Чого немає навмисно:** синтез натискань клавіш і миші (`generate_keyboard_event`, `generate_mouse_event`), перенесення фокусу, виділення тексту в чужих програмах.
- Шину доступності інструмент знаходить через `org.a11y.Bus.GetAddress` (єдиний виклик сесійної шини в його маніфесті); з `/run/user/<uid>` він бачить лише `at-spi/`. Сама шина доступності через проксі не йде: виклики AT-SPI однакові до будь-якої програми, тож фільтр за методом нічого б не дав, і межа тут — перевірка процесу в інструменті та рівні Herkos.
- Прочитане через AT-SPI — зовнішній вміст: після `list_windows` чи `read_window` сеанс забруднений, і далі діє Keros (розд. 6).

## Наслідки

- «Невідомі методи заборонено» тепер не обіцянка коду інструмента, а фільтр шини, який задає маніфест. Додати виклик GNOME — це рядок у маніфесті з рівнем, і без нього виклик не пройде.
- Gloxi може допомогти з дозволами програм («забери в цієї програми камеру») і з програмами без власного MCP через AT-SPI, але кожен клік у чужій програмі — R3 з показом кнопки.
- Ціна: на кожен інструмент з `dbus` — ще один процес `xdg-dbus-proxy` (пакет `xdg-dbus-proxy` з openSUSE, LGPL-2.1+, окремий процес, не бібліотека); список захищених програм треба підтримувати.
- Інструменти «налаштування» (dconf, PulseAudio) і «календар» (EDS) ще не за фільтром: EDS відкриває багато об'єктів і власних шин, перенести їх — наступний крок.
- Перевірено в контейнері: інструменти за фільтром із правилами маніфестів (несправжні служби на тестових шинах) і `vilna-mcp-atspi` з вікнами GTK 4 під Xvfb через справжню шину доступності, з фільтром, де дозволено лише `GetAddress`: вікно, запущене як `herkos-…`, не видно, пароль не прочитано, поле заповнено, кнопку натиснуто.
- Не перевірено: GNOME на Wayland в образі (MPRIS, `ScreenSaver.Lock`, сповіщення, справжнє сховище дозволів `xdg-permission-store`), Orca разом з `vilna-mcp-atspi`, юніти systemd і `xdg-dbus-proxy` під SELinux образу, діалог Herkos з рядками `describe`.

## Розглянуті варіанти

- **Перелік викликів лише в коді інструмента** (як зараз у «налаштуваннях»): нічого не гарантує, якщо інструмент зламано, і маніфест не каже, що він робить.
- **Окремий файл маніфесту D-Bus** поруч із маніфестом Herkos: два джерела правди для того самого методу. Рівень і виклик в одному рядку операції простіше перевіряти.
- **Політика dbus-broker / dbus-daemon** для uid інструмента: інструмент працює під uid людини, а правила сесійної шини людини Vilna не контролює.
- **AT-SPI через проксі з фільтром**: виклики однакові для будь-якої програми (`GetChildAtIndex`, `DoAction`), тож фільтр за методом не відрізнить менеджер паролів від редактора; межа — процес програми.
- **Ввести текст синтезом клавіш**: обходить перевірки поля (пароль, роль) і може потрапити в інше вікно, якщо фокус змінився.
