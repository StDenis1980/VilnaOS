# Протокол reports.vilnaos.com, версія 1

Стан: чернетка для Gloxi 0.2 і `vilna-reportd` (ADR 0018 розд. 2, 4–6). Код: [`protocol/src/lib.rs`](../protocol/src/lib.rs) — він і є еталоном; цей текст його описує.

Загальне:

- HTTPS, `application/json` у UTF-8, тіло до **64 КіБ** (більше — `413`).
- Невідомі поля ігноруються (новіший клієнт не отримує відмови). Обов'язкове поле з помилкою — `400` з `{"error":"invalid","field":"…","message":"…"}`; необов'язкове з помилкою сервер просто відкидає.
- Ідентифікатор кожного звіту й відгуку — **випадковий UUID версії 4**, який робить пристрій і зберігає в себе (`/var/lib/vilna-reports/sent/`). Постійного ідентифікатора пристрою немає. Знання номера — єдиний доказ, що запит іде з того самого пристрою, тому номер не показують нікому, крім людини.
- Повторне надсилання з тим самим `id` безпечне: сервер відповідає `200` з тим самим результатом і не рахує звіт удруге. Перший прийом — `201`.
- Ліміти в пам'яті на годину: 30 звітів про збій і 10 відгуків з однієї адреси, 120 інших запитів; на всіх разом — 5000 звітів і 500 відгуків. Понад ліміт — `429` з `Retry-After`. Клієнт чекає й пробує пізніше; сам пристрій надсилає не більше 20 звітів на день (ADR 0018 розд. 4).
- Сервер очищає текст удруге: адреси пошти, IP і MAC, шляхи, ряди з 6+ цифр стають `<email>`, `<ip>`, `<mac>`, `<path>`, `<n>`. Місце в коді Rust (`crates/x/src/y.rs:12`) і відносний файл нашого коду (`gloxi/chat.py`) лишаються.

## `POST /v1/crash` — звіт про збій

```json
{
  "schema": 1,
  "id": "3f2b8c1e-9a4d-4e7f-8b21-0c5d6e7f8a9b",
  "program": {"name": "org.gnome.Nautilus", "version": "48.2", "packaging": "flatpak"},
  "image": "Vilna Blavet 0.1",
  "kind": "signal",
  "signal": "SIGSEGV",
  "frames": [
    {"module": "libgtk-4.so.1", "build_id": "0a1b2c3d4e5f60718293", "offset": "0x4f2a1"},
    {"module": "nautilus", "build_id": "ffeeddccbbaa99887766", "offset": "0x1200", "function": "nautilus_window_open"}
  ],
  "locale": "uk",
  "arch": "x86_64",
  "memory_gb": 16
}
```

| Поле | Обов'язкове | Що |
| --- | --- | --- |
| `schema` | так | `1` |
| `id` | так | UUID v4 цього звіту |
| `program.name` | так | назва RPM або id Flatpak: літери, цифри, `. _ + -`, до 128 |
| `program.version` | ні | до 64 символів |
| `program.packaging` | ні | `rpm`, `flatpak`; інше — `other` |
| `kind` | так | `signal` (`systemd-coredump`), `exception` (Python: Gloxi, Herkos-lite), `panic` (Rust: `herkosd`) |
| `signal` | для `signal` | `SIGSEGV`, `SIGABRT`… |
| `exception` | для `exception` | лише назва типу: `KeyError`. **Ніколи** текст повідомлення |
| `location` | для `panic` | `crates/herkosd/src/gate.rs:12:5` |
| `frames` | ні | до 64 кадрів потоку, що впав, зверху вниз. Рідний код: `module` (лише ім'я файлу), `build_id`, `offset` (`0x…`), `function`, якщо вже є на пристрої. Python і Rust: `file` (відносно пакета: `gloxi/chat.py`), `line`, `function`. Кадри чужих пакетів Python не надсилаються |
| `image` | ні | версія образу Vilna |
| `locale`, `arch` | ні | `uk`, `pt_BR`; `x86_64`, `aarch64` |
| `memory_gb` | ні | сервер округлює вгору до степеня двійки |

Чого в звіті не буває ніколи (ADR 0018 розд. 2): дампа пам'яті, аргументів, змінних середовища, шляхів, імен користувача й комп'ютера, IP, назв мереж, тексту винятків, чужих журналів.

Відповідь `201`/`200`:

```json
{"id": "3f2b…", "signature": "0bba1215df5070e8", "status": "new"}
```

`status`: `new` — перший такий збій; `known` — уже бачили; `fixed` — виправлено, тоді є `fixed_in` (версія). **Сигнатура** — 16 шістнадцяткових цифр з програми, виду, сигналу чи винятку, місця без номерів рядків і восьми верхніх кадрів (функція, а без неї модуль і зсув). Пристрій може зберігати сигнатуру, щоб надсилати однаковий збій не частіше разу на день для версії.

## `POST /v1/feedback` — відгук

```json
{
  "schema": 1,
  "id": "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee",
  "kind": "bug",
  "channel": "gloxi",
  "text": "Копії зупинились на 40 %",
  "text_en": "Backups stopped at 40 %",
  "system": "Vilna Blavet 0.1, 16 GB, …",
  "crash_ids": ["3f2b8c1e-9a4d-4e7f-8b21-0c5d6e7f8a9b"],
  "locale": "uk",
  "program": "gloxi",
  "version": "0.2.0",
  "contact": "name@example.org",
  "may_publish": false
}
```

| Поле | Обов'язкове | Що |
| --- | --- | --- |
| `id` | так (JSON) | UUID v4; пристрій зберігає його, щоб можна було видалити |
| `kind` | ні | `bug`, `idea`, `other` (за замовчуванням) |
| `channel` | ні | `gloxi` (образ, R4 через Herkos), `window` («Відгук про Vilna»), `site` (за замовчуванням; і Flatpak Gloxi, що відкриває форму сайту) |
| `text` | так | до 8000 символів, той текст, який людина бачила й погодила |
| `text_en` | ні | машинний переклад локальною моделлю (ADR 0018 розд. 5, крок 4) |
| `system` | ні | блок про систему (як `gloxi check`), лише якщо людина погодилася; до 4000 |
| `crash_ids` | ні | до 10 номерів звітів про збій з цього пристрою |
| `contact` | ні | пошта для відповіді. Зберігається **окремо** від тексту, видаляється разом із відгуком, ніколи не публікується. Не пошта — `400` |
| `may_publish` | ні | людина дозволила перенести відгук у публічний issue після нашого перегляду |

Відповідь `201`/`200`: `{"id": "…"}`.

### Форма на сайті

Та сама точка приймає `application/x-www-form-urlencoded` без JavaScript: поля `kind`, `text`, `contact`, `may_publish` (`on`), `lang` (одна з 10 мов ADR 0009), `program`, `version`, `system` і приховане поле `website`, яке людина не бачить (бот, що його заповнив, отримує «дякуємо», а сервер нічого не зберігає). Номер робить сервер. Відповідь — `303` на `https://vilnaos.com[/<мова>]/feedback/thanks/`, а при помилці на `…/feedback/?error=<поле>#error-<поле>` (`text`, `contact`, `kind`, `server`): сайт без JavaScript, тож повідомлення про помилку показує CSS `:target` за якорем. Обидві сторінки — `site/src/pages/feedback.html` і `feedback-thanks.html`.

## `POST /v1/forget` — видалити свої звіти (GDPR)

```json
{"ids": ["3f2b8c1e-9a4d-4e7f-8b21-0c5d6e7f8a9b", "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee"]}
```

До 100 номерів звітів і відгуків. Відповідь: `{"deleted": 2}`. Невідомі номери не помилка. Лічильник сигнатури лишається: у ньому немає нічого про пристрій. Видалений рядок SQLite затирається (`secure_delete`).

## `GET /v1/status/<id>` — що з моїм збоєм

```json
{"id": "3f2b…", "status": "known", "issue_url": "https://github.com/StDenis1980/VilnaOS/issues/101"}
```

`status`: `unknown` (немає такого звіту або старший за 90 днів), `received`, `known` (є публічний issue), `fixed` (+ `fixed_in`). Нічого про інших людей і кількість звітів.

## Зберігання

- SQLite на сервері в ЄС. Звіти й відгуки — **90 днів** від прийому, далі видаляються щогодинним прибиранням; лишаються тільки лічильники за сигнатурою (програма, вид, назва, кількість, версії, перший і останній раз).
- IP-адреси, заголовки запитів і журнали доступу не зберігаються ніде: ні в базі, ні в Caddy, ні в журналі служби (журнал системи — 7 днів, без адрес).
- Issue з міткою `auto-report` у VilnaOS з'являється лише після того, як ми переглянули звіти й схвалили сигнатуру ([`operations.md`](operations.md)); далі коментар на 2, 5, 10, 25, 50… повторах, не більше 20 нових issue на день.
